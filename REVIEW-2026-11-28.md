# Pipeline review, 2026-11-28

Independent review of `main` at `dbe18613`, checked against the production
checkpoint on `codex-state` (`893bddad`, 2,150 tasks). The goal is a coding agent
that fixes issues, reviews its own work and opens clean PRs without supervision.

Every finding below is tied to a recorded task, a live command result or a file
and line. Anything that is an inference or was not verified is labelled.

## 3. Observed but not fixed

- **Task 1672** (`gh: Not Found (HTTP 404)`, respond) and **task 1970**
  ("review changed the patch; approval invalid"). The evidence bundles are
  encrypted, so the failing call and the changed file could not be identified.
- **Hermes creation denial.** Five fix tasks pushed an approved branch and were
  then refused at `gh pr create`. They remain in `error` with
  `publication_started`, and the repository hold needs a newer ordinary PR as
  proof. This is an upstream limit, not a code defect. Inference: GitHub's
  per-author open-PR limit for users without write access (June 2026) is the
  likely mechanism; the remedy is fewer open PRs or asking the maintainers.
- **`scope_check` and other controller refusals raise `RuntimeError`**, so they
  are recorded as `error` rather than `blocked`. Cosmetic, but it inflates the
  error count.

## 4. Recommendations

Ordered by expected effect on the goal: merged, clean PRs with little supervision.

1. **Measure merges, not opened PRs.** Track merged / closed / open per
   repository for the 94 published PRs and use it to decide which repositories
   stay enabled. Opened-PR counts hide whether the output is wanted.
2. **Stop racing, or shorten the queue wait.** Detection (5-second polling) and
   execution are not the slow part: over the last 45 days, first-attempt tasks
   that opened a PR took a median of 22 minutes from queueing (n=71). Tasks that
   lost to a competing PR had waited a median of 21 hours between queueing and a
   worker starting them (n=165, p25 21 minutes). The loss is queue wait under the
   call budget, one-task-per-repository rule and daily start caps. Either admit
   fewer candidates so each starts promptly, or
   admit only issues where speed does not matter: maintainer-confirmed,
   still unclaimed after a quiet period, and verifiable on Linux. Run the
   competing-PR and platform checks before a task is queued, not after checkout.
3. **Use the existing human-review workflow daily.** `human_review.py` and
   `codex-human-review.yml` already support a named exact-patch attestation.
   A few minutes a day converts the `human_wait` backlog into PRs and meets
   upstream oversight rules honestly. Full autonomy is not available on
   repositories whose rules require a human.
4. **Move execution to a small private VM.** OpenAI's CI guidance says not to
   use the `auth.json` login workflow for public repositories, and GitHub's
   Actions terms restrict hosted runners to work for the repository's own
   project. Whether the current setup breaches either is a reading, not a
   ruling. `local_service.py` and the SQLite queue already run outside Actions,
   and the move also removes checkpoint-by-git-push.
5. **Replace regex-over-prose classification with structured fields.**
   `task_recovery.wait_kind` and `codex_worker.failure_cooldown` decide task
   state from free text. Defect 3 is one instance. Add an explicit category enum
   to `GEN_SCHEMA` / `REVIEW_SCHEMA` and classify errors by type.
6. **Prune one-off code and prompt weight.** `task_recovery.py` hardcodes
   individual task IDs; up to 45,000 characters of `lessons/<repo>.md` go into
   every prompt; `AGENTS.md` is a chronological log, so current policy is hard
   to determine. Move the roughly 532 MB of encrypted evidence to object storage
   with a retention period.

A different agent framework (vendor cloud agents, SWE-agent, OpenHands, a
workflow engine) would replace the model-call loop or the queue but not change
the funnel in section 1. Their current capabilities were not evaluated in depth.

## 5. Follow-up changes on this branch

Measured first, then changed. Each has a regression test that fails without it.

| Change | Measurement behind it |
|---|---|
| Newest untouched fix task is claimed first; started work and feedback stay oldest-first (`codex_worker.next_queued`) | Over the 60 most recent lost races, the task was queued a median of 7 minutes after the issue opened and the competing PR arrived at 38 minutes. Only 2 of 60 competing PRs existed when the task was queued |
| OpenClaw untriaged wait lowered from 40 to 15 minutes (`scan.REPOS`) | On 182 queued OpenClaw issues, ClawSweeper's first label arrived at about 3 minutes and both positive labels within 10 minutes (p90). The 41 never-labelled issues were queued at a median of 43 minutes |
| OpenClaw issues with a ClawSweeper verdict but not both positive labels are declined (`scan.triage_declined`) | 38 such tasks in three weeks produced 0 PRs (30 skipped, 3 blocked, 2 validation holds, 2 still queued, 1 lost) |
| Reports from past contributors rank last among otherwise equal candidates (`scan.candidate_priority`; discovery now reads `authorAssociation`) | Of 583 issues, `CONTRIBUTOR` reporters opened their own closing PR on 36% (62 of 174) against 9% (33 of 363) for first-time reporters. Members and collaborators are not demoted: their issues drew fewer competing PRs |

Two things the measurements ruled out:

- **The model budget is not the limit.** Over seven days the trailing five-hour
  Codex call count had a median of 7 and a maximum of 41 against the cap of 45,
  and the provider quota read 31% used.
- **The workers were not down.** `Codex cloud live` ran back to back for the whole
  week (longest gap 0.4 hours). Codex calls occurred in only 56% of hours because
  nothing admissible was queued, not because the runner was absent.

What does bind: OpenClaw's 10 first-generation starts a day (reached on 5 of 9
days), its 20-open-PR cap (19 open), and what the starts are spent on. Of 222 fix
tasks that reached generation in 14 days, 19 opened a PR; 123 were skipped by the
model, 37 needed unavailable validation and 21 await human review.

The open-PR backlog is audited separately in `REVIEW-open-prs-2026-11-28.md`.
